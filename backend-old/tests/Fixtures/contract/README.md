# Recorded API contract

What the Slim backend returns today, recorded for Phase 0 of
[docs/laravel-migration.md](../../../../docs/laravel-migration.md). The Laravel backend is
done when it gives the same answers to the same requests.

One JSON file per case, grouped by resource. `index.json` lists every case under its route
in the plan's endpoint inventory, so each of the 43 routes can be checked for coverage. The
`spa/` cases are the SPA shell (`index.php`): the built `index.html` in `tests/Fixtures/spa/`
with each page's link-preview tags, requested with `Host: gallery.test`.

```bash
php bin/record-contract.php                 # re-record everything (from backend-old/)
php bin/record-contract.php --only=tags/    # re-record the cases whose id starts with tags/
php bin/record-contract.php --check         # exit 1 if a fresh recording differs from these files
```

The cases themselves are in `tests/Fixtures/contract-cases.php`. A full run takes about 25
seconds and never touches `backend-old/db`, `media`, `cache` or `logs`: the recorder copies the
app code to a temporary directory and serves it there with `php -S`
(`tests/Support/Contract/StagedApp.php`).

## The fixture

Every case starts from a fresh copy of:

- **Database:** `tests/Support/schema.sql` (the production schema), then
  `tests/Fixtures/contract.sql` (data only), plus one admin token inserted at the start of
  the case. The comments in `contract.sql` say which rows exist for which case.
- **Files:** `tests/Fixtures/media/thumbs/` (the `@2x` thumbnails the duplicate scan
  compares), an empty `media/full/`, and `tests/Fixtures/dupes/dupes-2026-10-30.json`
  (an old scan report, dated before any scan a case runs).
- **Config (`.env`):** `GALLERY_ADMIN_PASSWORD=contract-password`,
  `GALLERY_ALLOWED_ORIGINS=https://gallery.test,http://localhost:5173`,
  `GALLERY_URL=https://gallery.test`, `DANBOORU_LOGIN=contract`,
  `DANBOORU_API_KEY=contract-key`, and the duplicate-scan settings unset (defaults). A case's
  `setup.env` overrides these.
- **Danbooru:** `tests/Fixtures/danbooru-stub.php`, a stand-in for the three Danbooru calls,
  answering by the MD5 in the request. The staged copy of `DanbooruTagger` points at it.
- **Upload files:** `tests/Fixtures/uploads/`. `duplicate.png`'s MD5 is media 2's `hash`,
  and `tiny.png`'s MD5 is the one the stub matches, so regenerating either image means
  updating `contract.sql` or the stub to match.
- **Rate limits and response cache:** empty, so `X-RateLimit-Remaining` starts at 119 and
  the first cached read of a case is a `MISS`.

## A recording

```jsonc
{
  "id": "tags/create",
  "route": "POST /tags",                  // inventory row, or ANY /{unmatched} / OPTIONS /{any}
  "about": "…",                           // what the recording shows
  "setup": {                              // only when the case changes the fixture
    "env": { "DANBOORU_API_KEY": "" },    //   .env overrides
    "sql": ["DELETE FROM media"],         //   run on the fresh database
    "files": { "dupes": null },           //   paths under the app root: written, or removed if null
    "danbooru": "down"                    //   Danbooru unreachable
  },
  "steps": [
    {
      "probe": true,                      // a cache probe (see below)
      "repeat": 120,                      // sent this many times; only the last response recorded
      "statuses": { "200": 120 },         //   with the status of every send
      "request": {
        "method": "POST",
        "path": "/api/tags",              // exactly as sent, percent-encoding included
        "headers": { "Accept": "*/*", "Origin": "https://gallery.test", "Authorization": "Bearer <admin-token>" },
        "json": { "tag_name": "x" }       // or "form", "body" (raw), or "multipart"
      },
      "response": {
        "status": 201,
        "headers": { "content-type": "application/json", "x-ratelimit-remaining": "119" },
        "json": { "tag_id": 17 }          // or "text", or "sha256" + "bytes" for a large body
      },
      "danbooru_calls": ["GET /posts.json?tags=md5:…"]   // calls the stub received, credentials removed
    }
  ]
}
```

- **Request headers.** Reads send no `Origin` or `Authorization`, as a same-origin browser
  read doesn't. Writes send `Origin: https://gallery.test` and the admin token unless the step
  says otherwise. `Bearer <admin-token>` means the fixture's admin token, and
  `Bearer <captured:token>` means the token an earlier step's login returned. A `multipart`
  part names its fixture file (`file`) or a size of generated bytes (`generated_bytes`).
- **Response headers.** Only the ones in the contract are kept: `content-type`, `x-cache`,
  `x-ratelimit-remaining`, `retry-after`, `cache-control`, `allow`, the
  `access-control-*` set, `x-frame-options` and `x-content-type-options`. A header that's
  absent wasn't sent. `content-type` is dropped when the body is empty, since there it's
  PHP's default and not the app's.
- **Bodies.** A JSON body is stored decoded. HTML (Slim's error pages, `/api/docs`) is
  stored as `text`. `/api/openapi.json` is recorded by digest, with
  `"same_as": "backend/openapi.json"` (the spec the Laravel app must serve, identical to the Slim app's).
- **Cache probes.** A case marked `probe` reads `GET /api/media/count` (media group) and
  `GET /api/tags` (tags group) before and after its steps. A `MISS` afterwards means the
  write invalidated that group, and a `HIT` means it didn't.

## Comparing

Compare JSON bodies as decoded values: object key order doesn't matter, array order does.
These placeholders match any value of the stated kind:

| Placeholder | Where | Matches |
| --- | --- | --- |
| `<token>` | login `token` | 64 lowercase hex characters |
| `<seconds>` | `retry_after`, the `Retry-After` header, the scan's `execution_time` | a positive number |
| `<now>` | `file_time` of an upload, a new report's `generated_at` | the current time (an int, or `Y-m-d H:i:s` in the server's zone) |
| `dupes-<today>.json` | a new report's `report_file` | `dupes-` + today's date |

`ssim` values come from decoding the WebP thumbnails, which can differ in the last digits
between libwebp builds, so compare them to three decimal places. Every other value, the
perceptual fingerprints of uploads included, is exact.

## Recorded behavior the plan doesn't assume

These are how the app behaves today, so they're what the recordings hold. Before Phase 3,
decide for each one whether Laravel keeps it or the recording changes on purpose.

- **No route answers 404.** The OPTIONS catch-all `/{routes:.+}` matches every path, so an
  unmatched path gets **405 with `Allow: OPTIONS`** (`errors/unmatched-path`).
- **Slim, not the app, renders 405 and 500.** Its bodies are an HTML page for
  `Accept: */*` (what `fetch` sends) and `{ "message": … }` only for
  `Accept: application/json`, never `{ error, message }` (`errors/*`, `tags/update-name-taken`,
  `duplicates/dismiss-unknown-media`).
- **Preflight is 200 with an empty body, not 204.** The CORS middleware answers OPTIONS
  itself, before routing or rate limiting (`cors/preflight`).
- **Non-numeric ids are 400, not 404.** `/media/abc` and `/tags/abc` reach the controller
  and fail as id 0 (`media/show-invalid-id`, `tags/show-not-found`). The plan's
  `whereNumber()` would turn these into 404s.
- **Two writes 500 on bad input** instead of a 4xx: renaming a tag onto an existing name
  (UNIQUE constraint) and dismissing a pair with an unknown media id (foreign key).
- **The origin check runs outside the rate limiter.** A 403 from it carries no
  `X-RateLimit-Remaining` and isn't counted (`tags/create-origin-check`, `rate-limit/exceeded`).
- **Partial updates reset fields.** `PUT /tags/{id}` without `category_id` moves the tag to
  category 1, and `PUT /tag-categories/{id}` resets an omitted `description` and `sort_order`.
  `POST /tag-categories` without `color` fails with `InvalidColor`, because the default is
  `white`.
- **Some writes report success without doing anything**: `PUT /danbooru/tag-mappings/{id}` and
  the DELETEs of mappings and implications return 200/204 for ids that don't exist.
- **`POST /tags/{id}/migrate` keeps the source tag**, and only moves its media. The docblock
  says it deletes it (`tags/migrate`).
- **Tag search page 0 isn't rejected** (`current_page: 0`), unlike the other listings, and an
  empty gallery's `/media/page` says `total_pages: 0` where the others say 1.
- **The login throttle is effectively 10 a minute, not 10 per 5 minutes.** Not recordable
  without waiting, but visible in `RateLimiter`: the global limiter's prune (60 s) runs first
  on every request and deletes the login limiter's older rows.
- **The SPA shell's tag search description `urldecode()`s the path**, so a raw `+` is a space
  (`c++` is described as "c"); the frontend sends `%2B`. Its pages carry no
  `X-Frame-Options` or `X-Content-Type-Options`, which only the API's middleware set.

## Not recorded

- **Thumbnails and video metadata.** The recording host had no `ffmpeg`/`ffprobe`. No
  response includes a thumbnail. The animated GIF upload's `width`/`height` fall back to
  `getimagesize` and `duration` is 0, where ffprobe would report the GIF's length.
- **A file over the real upload limit.** The staged server allows 1M uploads (production
  allows 100M), so a 1.5 MB file stands in for an oversized one (`media/upload-too-large`).
- **`ScanFailed` (500)** and the other "could not save" 500s. They need the database to fail
  mid-request.
- **Static files.** Production serves the built assets and `media/` files before
  `index.php`; the staged server sends every path outside `/api` to `index.php`.
